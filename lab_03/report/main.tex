\chapter{Task and short theory}
\section{Task 3.1 and the Romanian alphabet}
The objective of Laboratory Work No. 3 is to study classical ciphers that
use more than a fixed substitution of individual letters. My number in the
group list is 19. Since it is odd, the selected task is 3.1: implement the
Playfair cipher for Romanian messages, as specified in the assignment~\cite{ref:assignment}.
The program must accept encryption and decryption, require a key of at
least seven letters, reject invalid input clearly, and leave the final
restoration of word spaces to the user.

Playfair encrypts pairs of letters using a matrix built from a keyword.
The Romanian alphabet has 31 letters. In this implementation, J is treated
as I, so the matrix has 30 cells arranged in \textbf{six rows and five columns}.
The letter Î remains distinct from I. Uppercase and lowercase Romanian
letters are accepted; the cedilla variants of Ș and Ț are normalized.

The keyword's first occurrences are written into the matrix first. All
unused letters are then appended in Romanian alphabetical order. Messages
are converted to uppercase, ordinary spaces are removed, and J is replaced
by I. Identical letters within a pair are separated with X; Q is used
when the repeated letter is X. An unmatched final letter receives the
same choice of filler. Decryption keeps these fillers for manual interpretation.

\section{Encryption and decryption rules}
Let $A[r,c]$ be the matrix, using zero-based coordinates
$r\in\{0,\ldots,5\}$ and $c\in\{0,\ldots,4\}$. Let $d=1$ for encryption
and $d=-1$ for decryption. For a pair at positions $(r_1,c_1)$ and $(r_2,c_2)$:
\begin{itemize}
\item \textbf{Same row:} keep each row and replace each column by
      $(c+d+5)\bmod5$.
\item \textbf{Same column:} keep each column and replace each row by
      $(r+d+6)\bmod6$.
\item \textbf{Rectangle:} use the opposite corners $(r_1,c_2)$ and $(r_2,c_1)$.
      This rule is identical for encryption and decryption.
\end{itemize}
Thus encryption moves right or down, while decryption moves left or up.
The modulo operations implement wraparound. Adding the relevant dimension
keeps the remainder nonnegative during decryption.

Playfair substitutes letter pairs, which obscures simple single-letter
frequency relationships. It is nevertheless a classical educational cipher,
not a suitable method for protecting modern confidential communication.

\chapter{Implementation}

The C\# implementation contains two classes. \texttt{Program} manages the
menu, reads input, catches validation errors and repeats the corresponding
prompt. \texttt{PlayfairCipher} builds the matrix, prepares letter pairs,
encrypts and decrypts. The project targets .NET 10. The excerpts below
are taken directly from the current source~\cite{ref:source}; empty lines
are compressed for readability.

\section{Preparing pairs and inserting fillers}
\texttt{PreparePairs} scans the normalized message using an index. The
first letter of the next pair is \texttt{message[index]}. The filler is
X, except when that letter is itself X, in which case the filler is Q.
The following branches decide the second letter and how far to advance:
\codepart{172}{190}
\noindent\textit{Comment.} If only one letter remains, the method appends
a filler and consumes one original letter. If the next two letters are
identical, it forms a pair with a filler and also advances by only one:
the second original letter must be reconsidered. Otherwise, it consumes
both letters. Each constructed pair is added to a \texttt{List<string>}.

The prepared text is \texttt{BALXLOON}, or \texttt{BA LX LO ON}.
Only repeated letters inside the current pair are separated. For example,
\texttt{ABBA} already splits into \texttt{AB BA} and needs no filler.
For \texttt{XX}, the method produces \texttt{XQ XQ}; for a final X, it
produces \texttt{XQ}. This prevents an identical-letter filler pair.

\section{Transforming pairs and reversing the cipher}
\codepart{196}{225}
\noindent\textit{Comment.} \texttt{FindPosition} supplies the coordinates
of the two input letters. The three branches implement the same-row,
same-column and rectangle rules. \texttt{Encrypt} passes direction 1;
\texttt{Decrypt} passes direction $-1$. The result letters are read from
the matrix, and one short console line shows the input pair, output pair
and rule used.

During encryption, the message is normalized and sent through
\texttt{PreparePairs}. During decryption, the ciphertext is normalized and
split directly into two-letter substrings; no fillers are inserted.
Both methods concatenate the transformed pairs and return a string.

The console prints the normalized key, distinct keyword letters, matrix,
normalized message and prepared pairs before the transformations. Filler
insertions are reported where they occur. The final output is either the
ciphertext or the recovered prepared plaintext. Word spaces, capitalization,
the original I/J choice and ambiguous filler letters are not reconstructed
automatically.

\section{Verification coverage and source code}
For each of two keyed matrices, I checked all $30\times29=870$ ordered
pairs of distinct letters against an independent coordinate calculation,
then decrypted the results. Both sets passed: 1,740 pair cases in total.
The checks also covered repeated letters, alternate fillers, odd-length
plaintext, Romanian normalization, the minimum key length, invalid input
and decryption back to the prepared plaintext. The verification run passed
3,537 assertions. The source files were not modified while preparing this report.
