\section{Objectives and the Romanian alphabet}
The aim of Laboratory Work No. 1 is to implement the standard Caesar cipher
and a Caesar cipher with a keyword-based alphabet permutation, to understand
modular encryption and decryption, and to compare their security. Both tasks
use the 31-letter Romanian alphabet and the encoding specified in the
laboratory assignment~\cite{ref:assignment}.

Each letter is represented by its position, starting at zero. Table~\ref{tab:alphabet}
shows the complete encoding. Character codes such as ASCII or Unicode values

\section{Task 1.1: the standard Caesar cipher}
A Caesar cipher replaces every plaintext letter with the letter located a
fixed number of positions further along the alphabet. The secret key is an
integer $k\in\{1,2,\ldots,30\}$. For a plaintext index $x$ and a ciphertext
index $y$, encryption and decryption are
\begin{align}
 y &= E_k(x)=(x+k)\bmod 31,\\
 x &= D_k(y)=(y-k+31)\bmod 31.
\end{align}
Adding 31 during decryption prevents a negative remainder. This is sufficient
because the accepted key is at most 30. For example, with $k=3$, the letter
C has index 4 and becomes F, at index 7; Z has index 30 and becomes Â,
at index 2. Decrypting Â gives $(2-3+31)\bmod31=30$, which is Z.

The standard cipher has exactly 30 permitted keys; $k=0$ is excluded because
it would leave the text unchanged. An attacker can decrypt the ciphertext
with each of the 30 keys and inspect the candidates. This small key space
makes exhaustive search practical.

\section{Task 1.2: Caesar cipher with two keys}
The second version uses a numeric key $k_1\in\{1,\ldots,30\}$ and a keyword
$k_2$ containing at least seven Romanian letters. The keyword is converted
to uppercase. Its letters are placed first, retaining only the first
occurrence of each letter, and the unused letters of the Romanian alphabet
are appended in their original order. The resulting alphabet $P$ contains
all 31 letters exactly once.

If $\operatorname{pos}_P(a)$ denotes the position of letter $a$ in $P$, the
letter-level formulas are
\begin{align}
 E_{k_1,P}(a)&=P[(\operatorname{pos}_P(a)+k_1)\bmod31],\\
 D_{k_1,P}(b)&=P[(\operatorname{pos}_P(b)-k_1+31)\bmod31].
\end{align}
Both the lookup of the input letter and the lookup of the output letter use
the same permuted alphabet. The keyword changes the alphabet order, while
the numeric key determines the cyclic shift.

For $k_2=\texttt{CRIPTOGRAFIE}$, the distinct keyword letters are
\texttt{CRIPTOGAFE}. Appending the remaining letters gives
\begin{center}\small\ttfamily
CRIPTOGAFEĂÂBDHÎJKLMNQSȘȚUVWXYZ
\end{center}
With $k_1=3$, C at position 0 becomes P at position 3, while I at position 2
becomes O at position 5.

Considering every possible alphabet permutation gives the theoretical
number of parameter pairs
\[
 |K_{\mathrm{pairs}}|=30\cdot31!\approx2.47\times10^{35}.
\]
This counts pairs of a shift and an alphabet ordering, rather than keyword
strings: repeated letters can make different keywords produce the same
ordering. Different parameter pairs can also produce the same substitution,
so the number of distinct encryptions is at most $31!$. Restricting keywords
to ordinary words reduces the practical search space further.

Despite this larger theoretical key space, the cipher remains
monoalphabetic: a given plaintext letter always maps to the same ciphertext
letter. Letter counts and repeated-letter patterns are preserved under
renaming, so frequency analysis can still be used. Neither version provides
security suitable for protecting modern confidential information.

\texttt{RomanianAlphabet} provides shared normalization, validation, letter

\texttt{TwoKeyCaesarCipher} implements Task 1.2, and

\texttt{Program} manages the menu and input retry loops. The following
