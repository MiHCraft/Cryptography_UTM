\chapter{Task and short theory}
\section{Assigned task}
My number in the group list is $n=19$. The assignment uses $n\bmod11$ to
select the exercise, so $19\bmod11=8$ gives Task~2.8. The task is to compute
the 32-bit right half $R_k$ of a DES round from the previous left half
$L_{k-1}$ and the combined output of the eight S-boxes. The application must
accept manual or randomly generated inputs and display the table and
intermediate results used in the calculation~\cite{ref:assignment}.

\section{Where the calculation fits in DES}
DES processes 64-bit blocks in 16 Feistel rounds. Its 64-bit key representation
includes eight parity bits, leaving 56 bits for the key schedule. An initial
permutation produces the two 32-bit halves $L_0$ and $R_0$. Each round uses a
48-bit subkey $K_k$ and computes
\[
L_k=R_{k-1}, \qquad R_k=L_{k-1}\oplus f(R_{k-1},K_k).
\]
After the last round, the inverse initial permutation is applied to
$R_{16}\|L_{16}$ to obtain the ciphertext block~\cite{ref:fips}.

Inside $f$, expansion $E$ maps $R_{k-1}$ to 48 bits, which are XORed with
$K_k$. The result is split into eight 6-bit blocks $B_1,\ldots,B_8$.
Each S-box uses the outer two bits of its input to select a row and
the inner four bits to select a column, producing four output bits.
Concatenating the eight outputs yields the 32-bit word
$S=S_1(B_1)\|\cdots\|S_8(B_8)$. Task~2.8 starts with this word already supplied,
so the program computes $f=P(S)$ and then $R_k=L_{k-1}\oplus P(S)$.

\section{The DES permutation \texorpdfstring{$P$}{P}}
Read Table~\ref{tab:permutation} left to right, row by row. Its $j$-th entry
is the input position copied to output position $j$. Positions are counted
from the most significant bit, starting at one. Thus the first output
bit is input bit 16, and the last is input bit 25~\cite{ref:fips}.

\chapter{Implementation}
\section{Console input}
The application is written in C\# and targets .NET 10.
Option \texttt{1} prompts for $L_{k-1}$ and $S$ in hexadecimal.
\texttt{Convert.ToUInt32(input, 16)} accepts both \hex{12345678} and
\texttt{12345678}. An invalid menu choice repeats the menu prompt.
A format error or a value larger than \hex{FFFFFFFF} repeats the
corresponding hexadecimal prompt.

Option \texttt{2} uses \texttt{Random.Next(0, int.MaxValue)} to generate
each input. This limits generated words to \hex{00000000} through
\hex{7FFFFFFE}, so their most significant bit is always zero. Manual input
accepts the full unsigned 32-bit range.

\section{Bit selection and XOR}
\texttt{Program.cs} passes $S$ and $L_{k-1}$ to \texttt{Algorithm}.
The method \texttt{P} stores the permutation as a 32-entry byte array and
prints it before selecting bits. To read input position $p$, the code
shifts the 32-bit unsigned word right by $32-p$ and masks it with
\texttt{1}. It shifts the partial result left and appends the selected bit
using bitwise OR. After 32 iterations the accumulator contains $P(S)$.

The constructor computes \texttt{this.Rk = this.Ln\_minus\_one \string^ permutated}.
The C\# \texttt{\string^} operator XORs corresponding bits, yielding one where
they differ. The trace shows the inputs, the $P$ table, the permuted word,
and the XOR operands and result. Binary words are padded to 32 bits and
hexadecimal words to eight digits. The main program prints the value
returned by \texttt{getResult()}.
